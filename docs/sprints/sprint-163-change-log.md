# Sprint 163 Change Log

## Scope

Implemented the roadmap items from `docs/codebase-analysis-and-roadmap-2026-06-11.md` §4: catalog full-build slices, the Flow Designer evidence collector/builder/round-trip harness, the catalog fulfillment-flow convergence milestone (attach-existing only), ATF test plan generation, the Anthropic provider adapter, and intake story rewrite feedback.

## Changes

- Added reference qualifier serialization to the catalog item builder: a declarative encoded-query grammar (`field operator value` joined by `^`/`^OR`) validated fail-closed, rejecting `javascript:` and any script indicator before the qualifier reaches `item_option_new` XML.
- Added attachment of EXISTING variable sets to generated catalog items via deterministic `io_set_item` link updates; variable set names resolve against live `item_option_new_set` records and variable set creation remains refused.
- Added container grouping for generated catalog variables using `container_start`/`container_end` variables (type ids 19/20) so item variables no longer render as a flat list.
- Added fulfillment-flow attachment for generated catalog items: an EXISTING active record-triggered flow can be referenced through `sc_cat_item.flow_designer_flow`, resolved by a new fail-closed discovery resolver with stable reason codes `fulfillment_flow:not_found`, `fulfillment_flow:ambiguous`, `fulfillment_flow:inactive`, and `fulfillment_flow:not_record_triggered`. Flow creation and modification remain forbidden; the new `catalog_fulfillment_flows` maturity surface starts at 0.30, so attaching candidates route to manual review.
- Added `catalog_ui_policy_generate` for catalog UI policies (`catalog_ui_policy` + `catalog_ui_policy_action`): the same declarative condition/action subset as the form-level UI Policy builder, `run_scripts` and policy scripts rejected, and every referenced variable must be one of the item's own generated variables.
- Added `catalog_client_script_generate` for catalog client scripts (`catalog_script_client`): deterministic g_form-only rendering from declarative set/clear actions, re-validated through the shared client-script safety validators, restricted to the item's own variables.
- Kept both catalog behavior surfaces candidate-generation only at builder-maturity baseline 0.30; their customer-update XML shapes are recorded as UAT-unconfirmed evidence assumptions, so no retrieved Update Set handoff is created.
- Added `record_producer_create` for record producers (`sc_cat_item_producer` plus `map_to_field` variables): script-free declarative field mapping with fail-closed target-table and field discovery; any producer script request routes to manual review with reason code `record_producer:producer_script_manual_review`. Candidate generation only at maturity 0.30.
- Added `flow_xml_evidence.py`: a read-only Flow Designer XML shape evidence collector that validates retrieved `sys_update_xml` shapes against `flow-xml-shapes-v1`, records `latest_snapshot` currency, stores SHA-256 audit hashes instead of raw payloads, and redacts script bodies.
- Made the Flow builder readiness contract evidence-driven: it no longer hardcodes not-ready. `ready_for_runtime_generation` flips true only on a complete evidence set, and `ready_for_retrieved_update_set_handoff` additionally requires the deterministic builder availability signal. Runtime generation stays dark until real instance shape and snapshot evidence is collected.
- Added `flow_builder.py`: a deterministic graph-diff customer-update builder for the approved narrow subset (one additive action or one condition update on a record-triggered flow) with shape-repository-conformant output, deterministic sys_ids, and no snapshot mutation (`requires_resnapshot_on_import` marks the flow for platform re-snapshot).
- Added `flow_roundtrip.py`: a build → import to Retrieved Update Set → re-retrieve → assert-graph-equals-intent verification harness. The harness never previews or commits; ServiceNow-native preview/commit remains the human review boundary, and pre-commit runs yield typed pending-assertion reports usable as UAT evidence.
- Added `atf_test_generation.py`: typed `atf-test-plan-v1` artifacts derived from validated candidate changes, proposing `sys_atf_test`/`sys_atf_step` records with declarative out-of-box step configs only, `not_covered` reason codes for unmappable changes, and evidence assumptions for instance-version-sensitive step-config sys_ids. Plans attach fail-open in model fulfillment; a plan failure never fails the candidate.
- Added `anthropic_provider.py`: a Messages API adapter with structured output via `output_config.format`, fail-closed refusal and max-tokens handling, retry-after-aware retries, API key redaction, and request mapping at parity with the OpenAI adapter. Configured through `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`, `ANTHROPIC_BASE_URL`, and `ANTHROPIC_MAX_TOKENS` with default model `claude-3-opus-20240229`. Not yet wired into runtime provider selection; the provider registry decision is deferred.
- Added intake story rewrite feedback: gate-failing stories receive an `intake_feedback` artifact (`intake-feedback-v1`) with stable reason codes and a suggested rewrite, delivered through the existing allowlisted work-notes writeback, idempotent by content hash, and fail-open so feedback failures never block fulfillment.
